<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Releases tarball download | Network-fetched binary content |
| `~/.vault-memory/config.toml` write | Skill mutates server config |
| `.obsidian/plugins/vault-memory/` write | Skill places code into the user's vault |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-11-01 | Tampering | GitHub Releases tarball MITM | mitigate | Both skills verify SHA-256 against a `<tarball>.sha256` file in the same release; mismatch aborts before extraction (RESEARCH §"Security Domain") |
| T-07-11-02 | Tampering | `~/.vault-memory/config.toml` mutation | accept | Skill is user-initiated; the only mutation is setting `[plugin] enabled = true`; the change is documented in `SKILL.md` |
| T-07-11-03 | Spoofing | Fake release pretending to be vault-memory | mitigate | The repo URL is hard-coded in the scripts; user-trust comes from "the user explicitly ran the skill" |
| T-07-11-04 | Denial of Service | Malformed tarball | mitigate | The atomic-replace flow uses a side directory + mv; failure leaves the old version intact |
</threat_model>
