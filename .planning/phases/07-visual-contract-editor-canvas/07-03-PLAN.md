<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Plugin spawns `vault-memory serve` as child process | Child process inherits Obsidian's renderer environment + has filesystem + Ollama access |
| Plugin reads/writes `.obsidian/plugins/vault-memory/data.json` via `loadData`/`saveData` | Settings file may be synced via Syncthing/iCloud/git |
| `serverCommand` setting could be edited to point at an arbitrary binary | Future user-edited setting; not yet exposed via UI |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-03-01 | Elevation of Privilege | `serverCommand` setting | mitigate | Default value `"vault-memory"` relies on PATH resolution; the chrome plan (07-08) MUST require explicit confirmation when the user edits `serverCommand` to an arbitrary path (documented constraint, not enforced in this plan) |
| T-07-03-02 | Information Disclosure | `data.json` settings file synced cross-device | accept | Settings file contains no secrets — secrets land in 07-09 with ciphertext only; settings keys are connection URLs + model names that are not sensitive |
| T-07-03-03 | Denial of Service | Plugin fails to load when CLI missing | mitigate | Catch `CliNotFoundError`, continue plugin load, surface `Notice` + settings-tab banner — plugin remains operable for editing local `.contract` files even without server connectivity |
</threat_model>
