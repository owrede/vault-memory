  <behavior>
    SafeStorageAdapter:
    - Constructor: discovers `(window as { electron?: { safeStorage?: SafeStorage } }).electron?.safeStorage` once; stores reference; accepts an injected `safeStorage` for tests.
    - `isAvailable(): boolean` — wraps `isEncryptionAvailable()`; returns false when the platform path resolves to nothing.
    - `getBackend(): "basic_text" | "encrypted" | "unknown"` — calls `getSelectedStorageBackend()`; collapses non-`basic_text` values to `"encrypted"`; missing API returns `"unknown"`.
    - `encrypt(plaintext: string): string` — returns base64-encoded ciphertext via `safeStorage.encryptString(plaintext).toString("base64")`.
    - `decrypt(ciphertextBase64: string): string` — converts base64 → Buffer → `safeStorage.decryptString`; throws `DecryptFailedError` on failure.
    - Throws `BasicTextBackendError` on `encrypt` when `getBackend() === "basic_text"` UNLESS the caller passes `{allowBasicText: true}` (signals the user has acknowledged the warning).
    SecretsStore:
    - `Secret`: `{ name: string; ciphertext: string; createdAt: string (ISO-8601) }`.
    - Constructor: `(plugin: Plugin, safeStorage: SafeStorageAdapter)`.
    - `load(): Promise<void>` — reads `plugin.loadData()`, takes the `secrets` array sub-key, defaults to `[]`.
    - `save(): Promise<void>` — writes back the full data shape `{settings: …, secrets: […]}` preserving the settings sub-key.
    - `list(): readonly Secret[]` — returns name + createdAt projection (NOT ciphertext); the actual ciphertext stays internal.
    - `add(name: string, value: string, opts?: {allowBasicText?: boolean}): Promise<void>` — Zod-validates name (kebab-case 3–64 chars); rejects duplicates; encrypts via SafeStorageAdapter; appends to the array; saves.
    - `delete(name: string): Promise<void>` — removes the entry by name; saves.
    - `getCiphertext(name: string): string | undefined` — returns the ciphertext blob for the named secret (used by the connector resolution path; never returns plaintext).
  </behavior>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `data.json` synced via Syncthing/iCloud/git | Settings + ciphertext secrets cross-device; ciphertext is per-device-keyed (correct posture) |
| `safeStorage` API in Electron renderer | Per-RESEARCH Pitfall 3: not exposed via Obsidian public API; reached via `window.electron.safeStorage` |
| Linux `basic_text` backend | Effectively plaintext on disk; user must consent explicitly |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-08-01 | Information Disclosure | data.json synced cross-device with ciphertext | accept | Per-device ciphertext is the correct posture; sync substrate carries ciphertext that doesn't decrypt on the second device; user re-enters secret on new device |
| T-07-08-02 | Information Disclosure | Linux basic_text fallback | mitigate | Explicit warning banner; explicit user consent prompt before allowing add; recommendation to install gnome-libsecret/kwallet documented in SECRETS.md (07-12) |
| T-07-08-03 | Information Disclosure | Plaintext in memory | accept | Plaintext only present during the `encrypt` call; never written to disk; lives in the renderer process memory like every other Electron app secret |
| T-07-08-04 | Tampering | Settings hot-swap via MCP fails when CLI missing | mitigate | Local save proceeds; Notice surfaces; settings tab banner reminds the user the server is unreachable |
</threat_model>
