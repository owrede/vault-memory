- Output: `{ok: true, plaintext: string}` OR `{ok: false, reason: "decrypt_failed" | "safe_storage_unavailable"}`

`${secret:name}` reference syntax (CONTEXT D-CHROME-SECRETS):
- env_secrets values of the form `${secret:NAME}` indicate a secret resolved server-side at peer-MCP connect time
- Plugin decrypts ciphertext via safeStorage IN THE PLUGIN PROCESS; passes plaintext + name on the wire to `resolve_secret`; server uses it for substitution and never logs it
- Per-device ciphertext is the intentional security posture (CONTEXT D-CHROME-SECRETS); on safeStorage failure the user is prompted to re-enter the secret — no plaintext-fallback path

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Plugin → `set_mcp_client` tool | Tool input mutates server config — must be Zod-validated server-side (done in 07-04); the `{list: true}` variant is read-only (no FS mutation) |
| `${secret:name}` resolution path | Plaintext crosses the plugin → server stdio boundary; ciphertext stays in the plugin's data.json; safeStorage decrypt happens in the plugin process |
| Peer-MCP server connect "test" | A misconfigured peer can return arbitrary errors to the user UI |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-10-01 | Information Disclosure | `${secret:name}` resolution flow | mitigate | safeStorage decryption performed in the plugin process; plaintext passed to server's `resolve_secret` over local stdio only; server uses plaintext for substitution and never logs it; on `safe_storage_unavailable` the user is prompted to re-enter (no plugin-side plaintext-fallback path) |
| T-07-10-02 | Tampering | Adding a connector with a malicious command | mitigate | The `command` field is a free-text path with no UI confirmation — same trust model as the plugin's `serverCommand` (07-03); user is responsible; documented in CONNECTORS.md (07-12) |
| T-07-10-03 | Spoofing | "Test connection" returns false positive | accept | The test path uses the server's actual `Client.connect()` flow; the result is what the user will get at runtime |
</threat_model>
