<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Plugin → server `suppress_contract_write` MCP tool | Tool input controls when reload events are skipped — could be misused to suppress real edits |
| Server → plugin `vault-memory://contracts/reloaded` notification | Notification triggers a Modal in the plugin |
| SHA-256 hash computed on YAML body | If hash collision were possible, an attacker could replay a suppression entry (mitigated by SHA-256's collision resistance) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-07-01 | Tampering | `suppress_contract_write` tool input | mitigate | Zod-validated path (`_contracts/<name>.yaml` shape) + hash (64-hex); ttl bounded; gated by `[plugin] enabled`; structured error response on invalid input |
| T-07-07-02 | Tampering | Suppression bypass attempt | mitigate | TTL bounded ≤30s caps the window; hash mismatch on consume means the suppression entry is preserved for a later legitimate match while the current (different-body) event still fires reload |
| T-07-07-03 | Spoofing | Faked `contracts/reloaded` notification to client | accept | Notifications travel over local stdio; spoofing requires owning the server process — equivalent to running as the user |
</threat_model>
