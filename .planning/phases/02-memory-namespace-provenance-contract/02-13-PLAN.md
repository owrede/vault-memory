Close **WR-04**, **WR-07**, and **IN-04** — three findings in `src/memory/tools/record-observation.ts` plus a consolidated reason-code addition to `src/adapters/delivery/types.ts`:

- **WR-04 (warning):** Two coupled defects — (a) returns `{reason: 'permission_denied'}` on collision exhaustion (misleading; `permission_denied` means "vault is read-only" everywhere else); (b) uses deterministic salts `"0"`, `"1"`, `"2"` for collision retries, so three same-millisecond calls with the same claim ALL produce identical collision chains.
- **WR-07 (warning):** The `properties` escape-hatch merges caller-supplied keys LAST, so callers can override `source`, `evidence`, `confidence`, `observed_at`, etc. Documented as D-02 intent ("caller keys win") but unsafe for provenance: a caller can pass `properties: { evidence: [] }` and clobber the validated `args.evidence`. The audit trail then claims the lower-evidence content was MCP-validated when it wasn't.
- **IN-04 (info):** The `[U+0300-U+036F]` combining-diacritical-mark range in `slugify` uses literal combining characters that some editors / log tools render ambiguously and may silently strip. Functionally correct, fragile in source form.

**D-02 refinement note:** This plan refines locked decision **D-02** (the "caller-supplied properties win over sugar defaults" escape-hatch). The refinement: caller-supplied keys win for **contract-allowed extras** (e.g. `tags`, `expires_at`, `priority`) but NOT for the 8 provenance-critical keys (`source`, `evidence`, `confidence`, `observed_at`, `type`, `status`, `superseded_by`, `superseded_reason`). The validator at `DeliveryAdapter.write()` (Guard A / Guard B, Plan 02-03) remains the single source of truth for which non-protected keys the contract accepts; this plan tightens what the caller can SUPPLY before validation runs.
