<objective>
Close **WR-01**, **WR-02**, and **WR-03** — three findings in `src/memory/contract/loader.ts` where YAML contract shapes are silently dropped or silently overridden:

- **WR-01:** `ruleToZod` for `type: array` always emits `z.array(z.string())`, ignoring `items.type`. Contract authors writing `items: { type: 'number' }` get silent type drift.
- **WR-02:** `ruleToZod` for any `type` with `allowed: [...]` overrides the declared type with `z.enum(allowed)`. A `type: number` + `allowed: ['1', '2']` becomes a string enum.
- **WR-03:** The cross-field `when` parser uses regex `/^([A-Za-z_][A-Za-z0-9_]*)\s*==\s*'([^']+)'$/` and `continue`s silently on no match. Typos and unsupported forms (`!=`, `=`, double-quotes) produce rules that do nothing — undermining the contract guarantee.

All three findings share a root cause: **the loader is too permissive about malformed input**. The fix is fail-closed: any shape that cannot be soundly interpreted throws `MemoryContractInvalidError` at load with a diagnostic message naming the offending rule.

In scope:
1. Honor `items.type` in `ruleToZod` for `type: 'array'`. Support `string` (current default) and `number`. Reject any other `items.type` (including `date`, `datetime`, `boolean`, `reference`) with a load-time error.
2. Reject `allowed` when the declared `type !== 'string'` with a load-time error. (`allowed` is `z.array(z.string())` in the schema, so cross-typing it is always wrong.)
3. Reject unrecognized `when` expressions at load time. Compile each rule's `when` against the supported regex; if no match, throw `MemoryContractInvalidError` with the rule echoed back.
4. Author or extend `src/memory/contract/loader.test.ts` with the 8 cases listed under must_haves truths.

Out of scope:
- Extending the supported `when` syntax (e.g. adding `!=`, multi-clause). That's a future contract DSL extension — out of v2.0.0 scope. This plan tightens the rejection of unsupported shapes, not the expansion of supported ones.
- Schema changes to `src/memory/contract/schema.ts` (the `PropertyRuleSchema` and `CrossFieldRuleSchema` already declare the YAML field shapes correctly; the gap is solely in the Zod-builder).
- Changes to the shipped `default-memory-v1.ts` baseline contract (it uses string arrays, no number-typed allowed lists, and a single supported `when` form — already conformant).
</objective>
