RC tag dry-run strategy (W3 — no public-npm publish):

Per CONTEXT §"Specifics — No `v2.0.0-rc1` in the public NPM channel". v2.0.0-rc.1 MUST NOT appear on the public npm registry, and `npm unpublish` is not an acceptable fallback (it permanently burns the version number on npm and offers no advantage).

**Chosen approach (option a) — Temporary conditional in publish.yml:**
Add a guard to the `npm publish` step in `.github/workflows/publish.yml` that skips publication when `${GITHUB_REF_NAME}` matches `*-rc.*`. The Release-asset side (tarball build, manifest.sha256 generation, GitHub Release creation via `softprops/action-gh-release`) runs normally for `-rc.*` tags. After the RC dry-run completes and findings are recorded, the conditional is reverted before the live v2.0.0 cut (plan 08-08).

Concrete shape of the conditional (per W3):
```yaml
- name: Publish to npm
  if: ${{ !contains(github.ref_name, '-rc.') }}
  run: npm publish --access public --provenance
```
(or equivalent guard; planner picks the cleanest expression for the existing workflow syntax)

**Fallback approach (option b) — Fork repository:**
If for any reason the maintainer prefers not to land a temporary conditional in publish.yml on the canonical repo, push the RC tag from a fork (e.g., `owrede-test/vault-memory`) to exercise publish.yml end-to-end against a non-canonical npm package name + GitHub Release. Cleaner isolation but heavier setup. Document the decision in the SUMMARY.

**Explicitly rejected:** the previous draft's "let publish.yml run npm publish, then npm unpublish v2.0.0-rc.1 within 72 hours" path. npm policy: `npm unpublish` burns the version number permanently; it cannot be republished. The temporary-conditional path (a) and the fork path (b) both avoid this.

RC tag dry-run flow (option a — chosen by default):
1. Pre-flight: plans 08-01..08-06 landed on main; working tree clean.
2. On a throwaway branch `release-dry-run`: bump `package.json.version` to `2.0.0-rc.1` (`npm version 2.0.0-rc.1 --no-git-tag-version`); add the temporary `if: !contains(github.ref_name, '-rc.')` guard to the `npm publish` step in publish.yml. Commit both changes on the `release-dry-run` branch (NOT main).
3. Tag the `release-dry-run` HEAD: `git tag -a v2.0.0-rc.1 -m "v2.0.0-rc.1 dry-run (npm publish skipped)"`.
4. Push the tag (not the branch needed; the tag carries the workflow trigger): `git push origin v2.0.0-rc.1`.
5. Observe the workflow run via `gh run watch`. Confirm: `npm publish` step is SKIPPED (workflow log shows the condition evaluated false); tarball build step ran; manifest.sha256 generated; GitHub Release created with both assets attached and the CHANGELOG section as the body.
6. Verify on npm: `npm view @owrede/vault-memory@2.0.0-rc.1 version` returns "not found" (the canonical proof npm was not polluted).
7. Cleanup: `gh release delete v2.0.0-rc.1 --yes`; `git push origin :v2.0.0-rc.1`; `git tag -d v2.0.0-rc.1`; delete the `release-dry-run` branch locally and remotely. The conditional in publish.yml on the throwaway branch is discarded with the branch.
8. Document findings for plan 08-08.
